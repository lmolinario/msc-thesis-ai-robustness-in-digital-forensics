# Results

This directory contains the frozen metric tables and reporting artifacts used by
the experimental-results chapter (Chapter 6) of the thesis. It is a downstream
layer: datasets, perturbations, model predictions, commercial-tool exports, and
explainability assets are produced elsewhere.

## Historical Naming Note

The directory `results/figures/chapter_5/`, the `chapter5_*` reporting files, and
related validator wording originated before the final separation of implementation
and results into Chapters 5 and 6. These frozen names are preserved for artifact
identity and reproducibility. The final results are reported in
`docs/LatexThesis/sections/06_results.tex`.

## Canonical Metric Layers

Proxy metrics are generated by:

```text
evaluation/scripts/15_evaluate_proxy_models.py
```

The `proxy_model_*` files preserve task-specific views. The `final_*` files are
canonical reporting tables with stable schemas used by the figure generator and
cross-system comparison:

- `final_core_metrics.csv` contains clean and condition-level binary metrics;
- `final_robustness_metrics.csv` contains clean-to-perturbed comparisons;
- `final_confusion_matrices.csv` preserves the `[[tn, fp], [fn, tp]]` layout;
- `final_ood_metrics.csv` is the reporting alias of
  `proxy_model_ood_metrics.csv` and is intentionally byte-identical.

Columns historically named `confidence`, `confidence_mean`,
`confidence_shift`, or `high_confidence_*` contain proxy-model maximum
predicted-class probability (`Max-P`) information. These values are intra-model
diagnostic outputs and are not calibrated probabilities, forensic certainty, or
values directly comparable across architectures.

Commercial-tool metrics are generated after output normalization by:

```text
evaluation/scripts/19_normalize_forensic_ai_tool_predictions.py
```

The consolidated metric source of truth is:

```text
results/metrics/forensic_tools_metrics.csv
```

The per-tool CSV files are filtered views of the consolidated table.

## Canonical Commercial-Tool Predictions

The repository-wide prediction-level source for commercial tools is:

```text
evaluation/forensic_tools/normalized_predictions.csv
```

It contains 69,000 sanitized decisions covering six configurations and is
reconstructed from the validated public extracts by:

```text
forensic_tools/scripts/build_canonical_normalized_predictions.py
```

Its digest and source profile are recorded in:

```text
evaluation/forensic_tools/normalized_predictions_public_summary.json
```

Exact equivalence with the four source extracts and the frozen 186-row
commercial metric table is recorded in:

```text
forensic_tools/public_extracts_validation.json
```

The canonical table does not contain raw-export paths, local execution paths,
image hashes, unrelated EXIF values, PhotoDNA, device identifiers, or
case-management fields.

## OOD Accounting

The frozen dataset contains 500 unique OOD images. Each OOD image is evaluated
by all five fold-specific checkpoints of each proxy architecture:

```text
500 unique OOD images × 5 folds = 2,500 predictions per architecture
2,500 predictions × 3 architectures = 7,500 proxy OOD prediction rows
```

The value `total = 2500` must not be interpreted as 2,500 distinct OOD images.
It is the fold-aggregated prediction denominator for one architecture. OOD
remains separate from binary accuracy and F1 denominators.

## Reporting Assets

The main reporting entry point is:

```bash
python results/scripts/20_generate_experimental_reporting_assets.py
```

It reads consolidated metric tables and generates presentation-layer PDF, PNG,
and CSV artifacts. Source CSV/JSON metrics remain authoritative; figures must
not be edited to change numerical values.

Generated files under `results/figures/chapter_5/` are historical-path reporting
copies. Thesis-ready copies used by LaTeX are stored under
`docs/LatexThesis/images/`. Duplicate binary copies should be removed only after
hash-equivalence and reference validation.

## Embedded-Metadata Sensitivity Analysis

The frozen detailed workflow is retained as:

```text
results/scripts/21_generate_embedded_metadata_sensitivity_check.py
```

Its canonical prediction input is:

```text
evaluation/forensic_tools/normalized_predictions.csv
```

The detailed and aggregate outputs are retained under the historical reporting
path:

```text
results/figures/chapter_5/tab_embedded_metadata_sensitive_hits_detail.csv
results/figures/chapter_5/tab_embedded_metadata_tool_summary.csv
results/figures/chapter_5/tab_embedded_metadata_sensitivity_delta.csv
```

This is a leave-out sensitivity check. It does not establish that embedded
metadata causally influenced a proprietary tool decision.

An optional privacy-reduced workflow exists as:

```text
results/scripts/22_generate_public_embedded_metadata_sensitivity_check.py
```

It requires a separately generated minimized metadata audit and does not replace
the frozen detailed workflow unless explicitly executed and validated.

## Validation

Run the read-only validator from the repository root:

```bash
python results/scripts/23_validate_results_artifacts.py
```

It checks:

- 69,000 canonical sanitized commercial-tool decisions;
- the six 11,500-row tool/configuration profiles;
- absence of raw/local paths and forbidden columns in the canonical table;
- the canonical CSV SHA-256 against its summary and equivalence report;
- 186 frozen commercial metric rows;
- 40,500 proxy prediction rows and the frozen metric-table counts;
- byte identity of the two OOD metric aliases;
- the `500 × 5 = 2,500` OOD accounting per architecture;
- 41 rows and 24 unique asset IDs in the historically named reporting manifest;
- the 15-bundle and 90-row embedded-metadata sensitivity profile.

To produce a local JSON report:

```bash
python results/scripts/23_validate_results_artifacts.py \
  --report results/results_validation_summary.json
```

Do not commit the generated report until it has been reviewed.

## Reporting Rules

- Keep proxy and commercial-tool results clearly separated.
- Treat OOD samples separately from the binary accuracy denominator.
- Distinguish 500 unique OOD images from 2,500 fold-level predictions per
  architecture.
- Preserve sample counts, attack-target metadata, and confusion-matrix layout.
- Report clean-to-perturbed drops from the frozen source tables.
- Use `Max-P` terminology for proxy maximum predicted-class probability.
- Do not infer product-wide robustness from this protocol-specific evaluation.
- Do not publish raw commercial exports or local execution paths.
- Regenerate presentation assets from frozen metric tables rather than editing
  numerical values manually.

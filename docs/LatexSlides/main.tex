\section{Motivation and Research Problem}

\begin{frame}{Why this matters in Digital Forensics}
\begin{columns}
\begin{column}{0.54\textwidth}
\begin{itemize}
    \item AI-based forensic tools are increasingly used to \highlight{triage large image collections}.
    \item The analyst often relies on labels, tags, bookmarks or semantic retrieval outputs.
    \item In forensic contexts, a missed item is not only a technical error: it can become an \highlight{operational risk}.
\end{itemize}
\end{column}
\begin{column}{0.40\textwidth}
\begin{colorblock}[black]{sinteflightgreen}{Core message}
The thesis does not build another weapon classifier.\\[0.35em]
It evaluates whether AI-based forensic classification remains reliable when inputs are manipulated.
\end{colorblock}
\end{column}
\end{columns}
\end{frame}

\begin{frame}{Research question}
\begin{block}{Main question}
How robust are AI-based forensic image-classification and media-triage systems when exposed to realistic adversarial and anti-forensic input manipulations?
\end{block}

\smallgap
The study combines three perspectives:
\begin{enumerate}
    \item \highlight{Transparent proxy evaluation}: controlled models and known architectures.
    \item \highlight{Commercial black-box evaluation}: observable outputs from forensic tools.
    \item \highlight{Operational risk analysis}: false negatives, false positives, OOD behavior and traceability.
\end{enumerate}
\end{frame}

\begin{frame}{Research gap}
\begin{itemize}
    \item Existing evaluations often emphasize clean performance.
    \item Commercial forensic tools expose heterogeneous and partial decision signals.
    \item Robustness under anti-forensic image transformations is rarely assessed with an operational protocol.
    \item OOD behavior is often mixed with classification performance, instead of being analyzed separately.
\end{itemize}

\begin{colorblock}[black]{sintefyellow}{Gap addressed by this thesis}
A reproducible forensic evaluation framework that tests clean, OOD, adversarial and anti-forensic conditions under a common audit logic.
\end{colorblock}
\end{frame}

\section{Results and Interpretation}

\begin{frame}{Proxy-model results: what to show}
\begin{itemize}
    \item Start from clean performance to establish the baseline.
    \item Then show robustness degradation under adversarial and anti-forensic conditions.
    \item Highlight the strongest collapse case: EfficientNet-B0 under direct-target Sigma Zero.
    \item Emphasize that robustness differs across architectures and attack settings.
\end{itemize}

\begin{colorblock}[black]{sinteflightgreen}{Main sentence}
Clean performance does not imply operational robustness.
\end{colorblock}
\end{frame}

\begin{frame}{Commercial-tool results: what to show}
\begin{itemize}
    \item Do not present the tools as if they shared the same internal logic.
    \item Compare them through normalized observable signals.
    \item Focus on operational behavior: detections, misses, false alarms and no-decision cases.
    \item Show that effects are tool-specific and condition-specific.
\end{itemize}

\begin{block}{Defensible interpretation}
The thesis does not claim to reverse engineer commercial AI modules; it assesses their exported behavior under controlled forensic inputs.
\end{block}
\end{frame}

\begin{frame}{OOD behavior}
\begin{itemize}
    \item OOD samples test what happens outside the expected binary weapon/non-weapon setting.
    \item Forced labeling on OOD content can create operational noise.
    \item High-confidence or repeated OOD weapon tagging should be treated as a risk signal.
\end{itemize}

\begin{colorblock}[black]{sintefyellow}{Why this slide is important}
It shows that the problem is not only adversarial attacks. Robust forensic triage must also manage distribution shift.
\end{colorblock}
\end{frame}

\begin{frame}{Explainability and case studies}
\begin{itemize}
    \item Integrated Gradients is used to inspect selected proxy-model decisions.
    \item XAI is not treated as legal proof.
    \item Its role is diagnostic: understanding where the model focuses under clean and perturbed conditions.
\end{itemize}

\begin{block}{Message for the commission}
Explainability supports interpretation and debugging, but it does not replace validation, audit trails or human forensic review.
\end{block}
\end{frame}

\section{Forensic Implications}

\begin{frame}{Operational implications}
\begin{itemize}
    \item AI-based forensic tools are useful for prioritization and workload reduction.
    \item They should not be used as autonomous evidence selectors.
    \item Every AI-based triage result should be linked to tool version, configuration, export logic and validation context.
    \item Human review remains necessary, especially for negative or no-decision outcomes.
\end{itemize}
\end{frame}

\begin{frame}{Limitations}
\begin{itemize}
    \item Dataset size is intentionally controlled, not exhaustive.
    \item Commercial tools are black boxes: only observable outputs are evaluated.
    \item Some results depend on specific tool versions and export settings.
    \item The study does not claim universal validity across all forensic domains.
\end{itemize}

\begin{colorblock}[black]{sinteflightgreen}{How to phrase it}
These limitations are not weaknesses of the protocol; they define the exact operational perimeter of the experiment.
\end{colorblock}
\end{frame}

\begin{frame}{Conclusions}
\begin{enumerate}
    \item The thesis provides a reproducible framework for forensic AI robustness assessment.
    \item Clean accuracy alone is insufficient for evaluating forensic reliability.
    \item Output normalization is necessary for comparing black-box forensic tools.
    \item OOD behavior and false negatives are central operational risks.
    \item AI-based forensic classification should remain human-supervised and validation-driven.
\end{enumerate}
\end{frame}

\begin{frame}{Future work}
\begin{itemize}
    \item Extend the protocol to larger and more heterogeneous forensic datasets.
    \item Include additional media classes and tools.
    \item Repeat tests across tool versions to measure robustness drift.
    \item Explore stronger audit mechanisms for AI-assisted forensic triage.
\end{itemize}
\end{frame}

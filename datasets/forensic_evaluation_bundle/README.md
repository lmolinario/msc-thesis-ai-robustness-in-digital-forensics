# Forensic Evaluation Bundle

This directory is the operational bridge between the frozen academic pipeline
and the black-box forensic-tool evaluation.

The bundle is generated by:

```text
datasets/scripts/bundle/16_build_forensic_evaluation_bundle.py
```

## Composition

| Condition | Files |
|---|---:|
| Clean binary inputs | 1,000 |
| OOD inputs | 500 |
| Adversarial inputs | 5,000 |
| Anti-forensic inputs | 5,000 |
| **Total** | **11,500** |

The canonical counts and integrity checks are recorded in
`metadata/bundle_summary.json`.

## Main-branch policy

The 11,500 bundle image files are generated locally and are not tracked on
`main`. The public repository retains the generation scripts, anonymized bundle
manifests, hashes, summaries and minimized audit records required for
traceability.

Run step 16 after restoring or regenerating the controlled-access source images
to recreate the local `blind_tool_input/` and `structured_audit_view/`
directories.

## Directory roles

```text
forensic_evaluation_bundle/
├── blind_tool_input/        # generated locally; not tracked
│   └── files/
├── metadata/                # tracked public records + ignored private audit
└── structured_audit_view/   # generated locally; not tracked
```

### `blind_tool_input/files/`

This is the only directory intended for import into evaluated black-box tools.
Files use neutral bundle identifiers and a flat layout so that paths do not
expose labels, OOD status, folds, attack families, attack names, source models
or provenance.

### `metadata/`

This directory is for post-export normalization and audit. It must not be
imported into evaluated tools.

Canonical public files include:

```text
metadata/bundle_manifest.csv
metadata/bundle_hashes_sha256.csv
metadata/bundle_summary.json
metadata/embedded_metadata_audit.csv
metadata/embedded_metadata_sensitive_hits.csv
metadata/embedded_metadata_audit_summary.json
metadata/embedded_metadata_public_summary.json
```

The public embedded-metadata audit is generated by:

```bash
python datasets/scripts/bundle/17_build_public_embedded_metadata_audit.py
```

The complete audit produced by step 16 may contain full EXIF/XMP values and
binary metadata payloads. It is a local diagnostic artifact, not a public
research output. Step 17 preserves it locally as the ignored file:

```text
metadata/embedded_metadata_audit.private.csv
```

and installs a minimized public audit containing only:

```text
bundle_id
suffix
has_embedded_metadata
sensitive_hits
sensitive_hit_count
metadata_keys
```

This schema is sufficient to reproduce the embedded-metadata prevalence and
leave-out sensitivity analysis without redistributing complete metadata values.

### `structured_audit_view/`

This optional local view preserves a semantic hierarchy for controlled audit
and debugging. It is not a valid input view for blind tool evaluation.

## Bias-control rule

After local regeneration, tool operators must import only:

```text
datasets/forensic_evaluation_bundle/blind_tool_input/files/
```

They must not import `metadata/` or `structured_audit_view/`. This separation
reduces path-induced and analyst-induced bias while retaining hash-based
traceability for normalization.

## Integrity checks

The bundle-generation summary records checks for:

- unique bundle identifiers;
- unique actual SHA256 values;
- hash agreement with source manifests;
- semantically neutral blind paths;
- separation between tool inputs and metadata.

The embedded-metadata audit is non-destructive. It identifies metadata that
could expose semantic or experiment-specific information without modifying the
image files. Publication of the audit is subject to data minimization: complete
metadata values remain local or in the protected historical snapshot, while
`main` retains only the minimized schema and aggregate sensitivity outputs.

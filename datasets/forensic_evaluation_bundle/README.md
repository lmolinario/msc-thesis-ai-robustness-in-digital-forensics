# Forensic Evaluation Bundle

This directory is the operational bridge between the frozen academic pipeline
and black-box forensic-tool evaluation.

The bundle is generated by:

```text
datasets/scripts/bundle/16_build_forensic_evaluation_bundle.py
```

## Composition

| Condition | Files |
|---|---:|
| Clean binary inputs | 1000 |
| OOD inputs | 500 |
| Adversarial inputs | 5000 |
| Anti-forensic inputs | 5000 |
| **Total** | **11500** |

The canonical counts and validation checks are recorded in
`metadata/bundle_summary.json`.

## Directory roles

```text
forensic_evaluation_bundle/
├── blind_tool_input/
│   └── files/
├── metadata/
└── structured_audit_view/
```

### `blind_tool_input/files/`

This is the only directory intended for import into the evaluated black-box
tools. Files use neutral bundle identifiers and a flat layout so that paths do
not expose labels, OOD status, folds, attack families, attack names, source
models, or provenance.

### `metadata/`

This directory preserves ground truth and audit information for post-export
normalization. It must not be imported into the evaluated tools.

Canonical files include:

```text
metadata/bundle_manifest.csv
metadata/bundle_hashes_sha256.csv
metadata/bundle_summary.json
metadata/embedded_metadata_audit.csv
metadata/embedded_metadata_audit_summary.json
```

### `structured_audit_view/`

This optional internal view preserves a semantic hierarchy for controlled
audit and debugging. It is not a valid input view for blind tool evaluation.

## Bias-control rule

Tool operators must import only:

```text
datasets/forensic_evaluation_bundle/blind_tool_input/files/
```

They must not import `metadata/` or `structured_audit_view/`. This separation
reduces path-induced and analyst-induced bias while retaining full hash-based
traceability for normalization.

## Integrity checks

The bundle-generation summary records checks for:

- unique bundle identifiers;
- unique actual SHA256 values;
- hash agreement with source manifests;
- semantically neutral blind paths;
- separation between tool inputs and metadata.

The embedded-metadata audit is non-destructive. It reports metadata that could
reveal semantic or experiment-specific information without modifying the image
files.

## Distribution status

The repository's final policy for retaining or removing the image corpora from
`main` is handled separately from this documentation cleanup. In either case,
the metadata, manifests, hashes, scripts, and normalized outputs remain the
canonical reproducibility record.

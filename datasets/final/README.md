# Final Dataset

This directory contains the manually selected frozen dataset and the audit artifacts generated by the human-in-the-loop selection protocol.

The final dataset is the methodological anchor for all subsequent steps:

- clean split generation;
- adversarial perturbation generation;
- anti-forensic transformation generation;
- OOD evaluation;
- forensic evaluation bundle construction;
- local model evaluation;
- forensic tool evaluation.

## Dataset composition

The final frozen dataset contains 1500 images.

| Group | Count | Role |
|---|---:|---|
| `weapon` | 500 | Positive class for the nominal binary task |
| `non_weapon` | 500 | Negative class for the nominal binary task |
| `ood` | 500 | Out-of-distribution and borderline evaluation set |

The adversarial and anti-forensic subset contains 1000 images.

| Group | Count | Role |
|---|---:|---|
| `weapon` | 500 | Attack target class |
| `non_weapon` | 500 | Attack target class |

OOD images are not attacked. They are evaluated separately to analyze how models and forensic tools behave on anomalous, borderline, synthetic, or semantically out-of-distribution inputs.

---

## Class definitions

### `weapon`

The `weapon` class includes realistic images containing clearly visible individual firearms.

Included examples:

- pistols;
- revolvers;
- rifles;
- shotguns;
- submachine guns;
- partially visible firearms, if still semantically recognizable.

This class is intentionally conservative. It is restricted to realistic firearm-related images to preserve the internal validity of the nominal binary benchmark.

### `non_weapon`

The `non_weapon` class includes realistic negative samples with no visible weapon.

Included examples:

- people without weapons;
- ordinary indoor or outdoor scenes;
- everyday objects;
- vehicles;
- documents, money, credit cards, drugs, or other investigative objects when they do not contain weapons.

These samples are negative with respect to the weapon-detection task, even when they may be relevant in broader investigative contexts.

### `ood`

The `ood` class includes borderline, anomalous, synthetic, degraded, or semantically out-of-distribution samples.

Included examples:

- knives;
- swords;
- machetes;
- toy guns;
- replicas;
- airsoft weapons;
- video game weapons;
- synthetic renders;
- stylized images;
- tanks;
- missiles;
- explosions;
- war scenes;
- extremely degraded images;
- abstract or indecipherable samples;
- memes and collages.

OOD is separated from the nominal binary benchmark to avoid expanding the semantic definition of the positive class beyond the intended forensic image classification task.

---

## Inclusion and exclusion policy

| Image category | Label | Methodological rationale |
|---|---|---|
| Pistols, revolvers, rifles, shotguns, submachine guns | `weapon` | Core positives for the nominal task; realistic individual firearms |
| Partially visible but recognizable firearms | `weapon` | Included when the firearm remains semantically clear |
| Realistic scenes without visible weapons | `non_weapon` | Clean negatives, coherent with the task domain |
| People without weapons, ordinary environments, common objects | `non_weapon` | Realistic negatives useful for binary evaluation |
| Drugs, documents, credit cards, money | `non_weapon` | Investigatively relevant but not part of the positive class |
| Knives, swords, machetes | `ood` | Broadly weapon-like but outside the firearm-centered benchmark |
| Toy guns, replicas, airsoft weapons | `ood` | Visually similar but semantically distinct from real firearms |
| Video game weapons, renders, stylized images | `ood` | Outside the realistic photographic domain |
| Tanks, war aircraft, missiles, explosions, war scenes | `ood` | Weapon systems or scenarios outside the individual-firearm task |
| Extremely degraded, abstract, or indecipherable images | `ood` or `exclude` | Not reliable enough for the nominal binary benchmark |

## Human-in-the-loop protocol

The dataset was built through a documented human-in-the-loop process.

This choice is methodological:

- the target class is semantically sensitive;
- commercial forensic tools may use broad and undocumented categories such as `weapons`;
- the thesis requires a conservative and defensible definition of the positive class;
- ambiguous cases must be traceable rather than silently absorbed into the binary task.

The reviewer protocol produces:

- selected final samples;
- removed or excluded samples;
- logs;
- summary reports;
- reviewer state;
- reproducible manifests for downstream experiments.

## Reproducibility requirements

Downstream scripts should never rely only on filenames.

Every sample should remain traceable through:

- `image_id`;
- final label;
- source;
- fold, when applicable;
- relative path;
- SHA256 hash;
- attack family and attack name, when applicable.

The frozen manifest should be treated as immutable once experiments begin.

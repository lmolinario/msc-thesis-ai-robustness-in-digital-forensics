# Datasets

This directory contains the dataset artifacts used in the thesis pipeline, from raw acquisition to final split generation and forensic evaluation bundle construction.

The dataset workflow follows a human-in-the-loop methodology: raw heterogeneous sources are first technically validated and deduplicated, then manually reviewed and frozen into the final thesis dataset.

## Raw Data

Raw acquired data are stored in:

```text
datasets/raw/
```

This directory contains the original source groups used to build the prepared dataset.

Important distinction:

```text
datasets/raw/                  = raw acquired data
datasets/scripts/acquisition/  = acquisition scripts
```

The `datasets/raw/` directory must not be renamed to `acquisition`.

## Prepared Dataset

The prepared dataset is generated by:

```text
datasets/scripts/prepared/08_build_prepared_dataset.py
```

It performs:

- image discovery;
- technical validation;
- minimum size filtering;
- SHA256 computation;
- exact duplicate removal;
- copy into the prepared image pool;
- technical metadata generation;
- invalid-image and duplicate-discard reports.

Main output:

```text
datasets/prepared/final_pool/metadata.csv
```

The prepared dataset is a technical pool. It does not contain the final semantic class selection.

## Forensic Evaluation Bundle

The forensic evaluation bundle is generated by:

```text
datasets/scripts/bundle/16_build_forensic_evaluation_bundle.py
```

Output directory:

```text
datasets/forensic_evaluation_bundle/
```

Methodological purpose:

- provide blind file inputs for forensic AI tools;
- avoid leaking class, attack, or provenance information through filenames shown to tools;
- preserve internal traceability through metadata and hashes;
- support post-export normalization and audit of commercial forensic-tool outputs.

Logical areas:

```text
datasets/forensic_evaluation_bundle/blind_tool_input/
datasets/forensic_evaluation_bundle/metadata/
datasets/forensic_evaluation_bundle/structured_audit_view/
```

The bundle includes clean images, adversarial outputs, anti-forensic outputs, and OOD samples selected for black-box forensic-tool evaluation.

## Traceability

Dataset traceability is based on:

- stable `image_id` values;
- SHA256 hashing;
- MD5 hashing for forensic tool compatibility;
- source metadata;
- relative paths;
- stage-specific manifests;
- manual review logs;
- split generation summaries;
- attack manifests;
- forensic bundle metadata;
- normalized forensic-tool outputs;
- XAI case-study manifests and thesis figure references where applicable.

SHA256 is the primary integrity hash for the thesis pipeline.
